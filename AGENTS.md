# Номера FIX-сессий 05.11.2026

- Пользователь 05.11.2026 поручил решать по сбросу номеров самостоятельно. Адаптер QUIK (`QUIK-SRV-TEST`, версия 4.7.0) хранит номера в `SystemInfo` и сам их не сбрасывает; при входе с 141=Y он обнуляет их и очищает архив отправленного (документация ARQA в `C:\Users\krahmanberdiev\Desktop\ARQA\Документация\`).
- По поручению пользователя 05.11.2026 FIX-адаптеры QUIK выключаются в 04:00 и запускаются в 09:05 (по Бишкеку); шлюз подключается к ним только в рабочее время. `FIX_SESSION_HOURS` (по умолчанию `09:05-03:59`, время Бишкека; пустое — без расписания, так у локального симулятора): вне окна менеджер не запускает адаптеры и не пытается подключаться, в 03:59 сам выходит с Logout, в 09:05 подключается снова (проверка раз в 10 с). Включение адаптера вне окна только сохраняет флаг, перезапуск отклоняется. Плановая пауза — не авария: `FIX_SESSION_DOWN` и «устранение» `FIX_SEQUENCE_RESET_*` не пишутся, метрика `gateway_fix_session_paused` = 1 исключает паузу из правила `AllFIXSessionsUnavailable`.
- QuickFIX-сессия шлюза не имеет своего расписания (`StartTime`/`EndTime` не задаются): с расписанием QuickFIX сбрасывал бы номера в начале каждого дня, поэтому окно соблюдает менеджер, а не QuickFIX. При остановке шлюз ждёт HTTP не дольше 5 с и параллельно отправляет Logout по всем адаптерам; `stop_grace_period` шлюза в compose — 30 с.
- Адаптер QUIK при ежедневном запуске в 09:05 начинает номера с 1 (проверено 06.11.2026: без сброса шлюз 36 минут отказывал во входе с «MsgSeqNum too low»). Поэтому первый вход рабочего дня (плановый запуск в 09:05) идёт с 141=Y. Страховка на перезапуск QUIK днём или запуск шлюза после него: если шлюз отказал Logon QUIK с «MsgSeqNum too low» или три Logon подряд не дали входа, следующий Logon идёт с 141=Y (`resetNextLogon` в `arqa/session_app.go`); после входа признак снимается. Внутри дня номера продолжаются без сброса.

Откат — `UPDATE adapters SET reset_on_logon=true WHERE id='<адаптер>'` и перезапуск шлюза.
