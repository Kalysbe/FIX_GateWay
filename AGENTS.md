# Источник текущих заявок 22.10.2026

- По поручению пользователя текущие заявки читаются из `quik_export2.public."Orders"` PostgreSQL QUIK `192.168.0.89:5432`, через отдельное соединение только для чтения.
- Списки, карточки текущих заявок и `order.updated` используют эту таблицу. Для брокера `FirmId` ограничивается `quik_firm` авторизованного токена, а при пустом значении — кодом брокера. Клиентские параметры не расширяют доступ.
- Строки `Orders` передаются в исходном виде: имена полей, числовые JSON-значения, строки и `null` сохраняются. Не добавлять служебные поля, рассчитанные статусы, объёмы исполнения, историю FIX или трассировку. Список REST — массив строк БД, карточка — одна строка. В gRPC исходный JSON передаётся в `Event.data_json` без преобразования чисел в double; признак удаления находится только в конверте события.
- Локальные `orders`, FIX и outbox сохраняются для приёма/отправки команд, идемпотентности и аудита. Они не являются запасным источником текущего списка. Исчезновение строки из `Orders` не доказывает отмену, истечение срока или исполнение и не переписывает историю.

# Решение по хранению сделок


- 16.10.2026 пользователь назначил на понедельник, 19.10.2026, пересмотр структуры хранения сделок. До этой работы текущую реализацию нельзя считать окончательным решением.
- Требование: хранить номер сделки QUIK и обе реальные стороны сделки в БД. Пользователь сообщил о множестве пропущенных вторых сторон; необходимо установить причину, восстановить пропуски и обеспечить полноту дальнейшей загрузки с проверкой по QUIK.
- Строка «Контрагент · FIX», построенная интерфейсом из одного отчёта, не заменяет сохранение второй стороны. Не подменять недостающие реальные данные выдуманными исполнениями или заявками.
- Подробности и критерии предстоящей работы: [docs/trades.md](docs/trades.md), раздел «Решение и результат пересмотра 19.10.2026».

## Пересмотр выполнен 19.10.2026

- Пользователь явно разрешил чтение истории через QUIK API `http://192.168.0.89:5000` для сверки и восстановления сделок. Это разрешение не распространяется на исходники, настройки или контейнеры других проектов и на торговые операции.
- Новые сделки хранятся в `trades`, реальные стороны — в `trade_sides`, источники — в `trade_reports`. `executions` остаётся реестром исполнений локальных заявок. Не возвращаться к построению отсутствующей стороны в интерфейсе.
- История QUIK содержит 11 167 сделок / 22 334 стороны. Исходная БД имела 21 164 исполнения; восстановление в новом реестре добавляет 1 170 реальных сторон, включая 69 целиком отсутствовавших сделок. Подробности, причины и проверки — в `docs/trades.md`.
