# API для брокеров: REST + gRPC

REST создаёт и отменяет заявки и возвращает текущие данные. gRPC передаёт обновления заявок, сделок, позиций и рынка.

## Подключение

| Интерфейс | Адрес / контракт | Авторизация |
|---|---|---|
| REST | `https://<host>`; JSON; схема `/broker-swagger` | Заголовок `Authorization: Bearer <API-токен>` |
| gRPC | `<host>:<port>`; RPC `/fixgateway.realtime.v1.RealtimeService/Stream` | Metadata `authorization: Bearer <API-токен>`; `x-client-type: broker` необязателен |

Подключение: VPN + TLS + API-токен. Клиентские сертификаты и HMAC по умолчанию не требуются. Оператор ограничивает доступ к API сетью VPN.

Для gRPC нужны TLS 1.3 и проверка сертификата сервера: системное доверие или CA оператора. Адреса и токен выдаёт оператор. Protobuf-контракт: [realtime.proto](../backend/proto/realtime/v1/realtime.proto). При отдельно включённом mTLS также нужны клиентский сертификат и ключ.

Заявки, сделки и счета ограничены текущим брокером. Позиции фильтруются по коду брокера и `quik_firm` токена. Рыночные данные общие. Заявки, сделки, котировки, инструменты и рыночные данные дополнительно ограничены классами QUIK, выбранными администратором шлюза (ничего не выбрано — все классы). Заявка в другом классе отклоняется как `INSTRUMENT_NOT_FOUND`, но уже принятую заявку можно отменить в любом случае.

Цены, суммы и количества в ответах — строки. В REST-запросах десятичные значения принимаются строкой или числом. `created_at`, `updated_at` и другие временные метки — RFC 3339; `clearing_date` и `trade_date` — торговые даты из QUIK.

## Формат ответа

Все REST-методы брокера отвечают в одном формате — и при успехе, и при ошибке:

```json
{"success": true, "code": "OK", "message": null, "error_code": null, "data": { ... }}
```

| Поле | Значение |
|---|---|
| `success` | `true` — запрос выполнен; `false` — ошибка или QUIK ещё не ответил |
| `code` | `OK` при успехе, иначе код ошибки (таблица в разделе «Ошибки») |
| `message` | Причина ошибки текстом; `null` при успехе |
| `error_code` | Код причины от QUIK (отказ заявки — FIX 103, отказ снятия — FIX 102); `null` при успехе и когда QUIK кода не прислал |
| `data` | Результат: объект, массив строк QUIK или `null` у ошибки |

Списки (`/orders`, `/orders/active`, `/trades`, `/market-data`, `/quotes`, `/accounts`) дополнительно содержат `has_more` и `next_offset` (те же значения, что в заголовках `X-Has-More` и `X-Next-Offset`). Строки QUIK внутри `data` передаются без изменений.

Отказ QUIK и ожидание ответа QUIK возвращают заявку в `data`:

```json
{"success": false, "code": "ORDER_REJECTED", "message": "No right for this trading account", "error_code": 8637225,
 "data": {"OrderNum": null, "State": "Отклонена", "RejectReason": "No right for this trading account", "id": "4efb2c8e-…", "...": "…"}}
```

Обработка: проверьте `success`; при `false` решение принимайте по `code`, точная причина от QUIK — `error_code`, текст для пользователя — `message`. Все значения `code` и известные `error_code` отдаёт `GET /api/v1/errors`. HTTP-код ответа сохраняется (`200`, `201`, `202`, `4xx`, `5xx`).
## Токен, счета, инструменты

### Изменение контракта 03.11.2026

`GET /api/v1/firm` заменён на `GET /api/v1/token`: общая информация о токене, его брокере и фирме. Строка QUIK `Firms` лежит в поле `firm`.

`GET /api/v1/token` доступен любому действующему токену; счета и инструменты требуют `orders:read`. gRPC-событий для этих справочников нет.

| REST | Назначение | Ответ `200` |
|---|---|---|
| `GET /api/v1/token` | Информация о токене | `token` — `id`, `name`, `description`, `token_prefix`, `status`, `permissions`, `firm_id` (фирма заявок), `expires_at`, `created_at`, `last_used_at`; `broker` — `code`, `name`, `status`; `firm` — строка QUIK `Firms` как есть или `null`, если фирмы там нет |
| `GET /api/v1/accounts` | Торговые счета фирмы токена | JSON-массив строк таблицы QUIK `Trdaccs` как есть |
| `GET /api/v1/instruments` | Инструменты выбранных биржей классов | JSON-массив строк таблицы QUIK `Securities` за последнюю дату как есть; `limit`, `offset`, `has_more`, `next_offset` |

Фирма, счета и инструменты берутся из БД QUIK (`Firms`, `Trdaccs`, `Securities`); имена колонок и значения не меняются. В `Account` заявки передавайте `TrdAccId` счёта своей фирмы: заявка принимается, только если в `Trdaccs` есть строка с этим `TrdAccId` и `FirmId` фирмы токена. Если источник QUIK недоступен, ответ — 503. Для инструмента передавайте его `SecCode` и `ClassCode`.

## Заявки

| REST / gRPC | Назначение | Возвращаемые данные | Право |
|---|---|---|---|
| `POST /api/v1/orders` | Создать заявку | Заявка в именах колонок QUIK `Orders` после ответа QUIK; `201` — принята QUIK, `422` — отклонена QUIK, `202` — QUIK ещё не ответил | `orders:create` |
| `GET /api/v1/orders` | Строки Orders своей фирмы | Массив исходных строк БД | `orders:read` |
| `GET /api/v1/orders/active` | Сегодняшние строки Orders своей фирмы с `State` = `Активна` | Массив исходных строк БД | `orders:read` |
| `GET /api/v1/orders/{id}` | Одна текущая строка Orders | Исходная строка БД в `data` | `orders:read` |
| `POST /api/v1/orders/{id}/cancel` | Снять заявку; тело не требуется | Заявка в именах колонок `Orders` после ответа QUIK; `200` — снята, `409` — QUIK не снял, `202` — QUIK ещё не ответил | `orders:cancel` |
| gRPC `order.updated` | Изменения сегодняшних строк Orders своей фирмы (проверка раз в 500 мс) | `event.data_json` — исходный JSON строки; `event.removed=true` удаляет её из текущего набора | `orders:read` |

Источник чтения — `quik_export2.public."Orders"`. `FirmId` ограничен `quik_firm`
авторизованного токена (при пустом значении — кодом брокера). Параметры клиента
не расширяют этот доступ. Список принимает `limit` 1–1000 (по умолчанию 200)
и `offset`; заголовки `X-Has-More` и `X-Next-Offset` задают продолжение. gRPC не отправляет
начальный список: загрузите его через REST. Изменения проверяются каждые две
секунды, включая заявки, поданные вне Gateway. Ошибка БД даёт 503 без подстановки FIX.

Ответ содержит только исходные столбцы `Orders`: `OrderNum`, `TradeDate`,
`ClassCode`, `FirmId`, `SecCode`, `Operation`, `State`, `Qty`, `Price`, `Balance`
и все остальные поля таблицы. Регистр, типы, числа и `null` сохраняются.
Служебные ID, рассчитанные статусы и объёмы, история и trace не добавляются.
Ключ URL `quik-20261022-LIST_GBA-22455` строится из даты, класса и номера;
в ответ он не включается. В gRPC для сохранения точности PostgreSQL numeric
используется `Event.data_json`, а не `Event.data` с числами double. Поле
`removed` принадлежит конверту события и не изменяет JSON строки.

GET также принимает `id` из ответа на создание, но только пока заявка открыта: через
несколько минут после закрытия в QUIK шлюз её больше не хранит и `id` даёт 404. Для
долгого хранения ссылки используйте ключ из даты, `ClassCode` и `OrderNum`. Отмена
принимает `id` или ключ QUIK, но требует заявки, поданной через шлюз, и активной
строки QUIK; для внешних заявок — 409. Исчезновение строки не означает
подтверждённую отмену или исполнение. Подробнее: [Заявки](orders.md).

### Создание: тело POST

Поля называются как колонки таблицы QUIK `Orders`.

| Поле | Обязательно | Значение |
|---|---|---|
| `ClassCode` | Да | Код класса инструмента |
| `SecCode` | Да | Код инструмента из справочника |
| `Operation` | Да | `Купля` / `Продажа` |
| `Price` | Нет | Цена > 0. С `Price` — лимитная заявка, без `Price` — рыночная |
| `Qty` | Да | Количество > 0 |
| `Account` | Да | `TrdAccId` счёта фирмы токена из QUIK `Trdaccs` |
| `ClientCode` | Да | Код клиента |

```json
{
  "ClassCode": "LIST_GBA",
  "SecCode": "GBA02270915",
  "Operation": "Купля",
  "Price": 400,
  "Qty": 1,
  "Account": "1-3101-006",
  "ClientCode": "006"
}
```

Срок заявки — день. `FirmId` определяется по `quik_firm` токена, валюта — по инструменту; их в теле нет. Неизвестные поля, в том числе прежние `account_id`, `symbol`, `board`, `side`, `quantity`, `price`, возвращают `400`.

Каждый POST создаёт новую заявку. После таймаута или сетевой ошибки сначала проверьте `GET /api/v1/orders`, и только если заявки там нет — отправляйте её снова; иначе она может быть выставлена дважды.

### Создание: ответ

Шлюз сразу отправляет заявку в QUIK и отвечает после ответа QUIK (обычно меньше секунды, ожидание до 10 с):

| Код | `code` | Значение |
|---|---|---|
| `201` | — | QUIK принял заявку; `OrderNum` — номер заявки в QUIK |
| `422` | `ORDER_REJECTED` | QUIK отклонил заявку; причина в `RejectReason` |
| `502` | `ORDER_FAILED` | Заявку не удалось передать в QUIK |
| `202` | `QUIK_ANSWER_PENDING` | QUIK не ответил за время ожидания. Заявка не отменена и может быть принята позже: итог — через `GET /api/v1/orders/{id}`, заново её не отправляйте |

```json
{
  "OrderNum": 26102912345,
  "State": "Активна",
  "ClassCode": "LIST_GBA",
  "SecCode": "GBA02270915",
  "Operation": "Купля",
  "Price": 400,
  "Qty": 1,
  "Balance": 1,
  "Account": "1-3101-006",
  "ClientCode": "006",
  "FirmId": "SENTI2004",
  "RejectReason": null,
  "id": "276d043c-6716-4ebd-a7b7-15904e760d40"
}
```

| Поле | Данные |
|---|---|
| `OrderNum` | Номер заявки в QUIK; `null`, пока QUIK её не принял |
| `State` | `Активна`, `Исполнена`, `Снята` или `Отклонена`; `null`, пока QUIK не ответил |
| `ClassCode`, `SecCode`, `Operation`, `Price`, `Qty`, `Account`, `ClientCode` | Как в запросе; `Price` = `null` у рыночной заявки |
| `Balance` | Неисполненный остаток |
| `FirmId` | Фирма токена |
| `RejectReason` | Причина отказа QUIK или `null` |
| `id` | Номер заявки в шлюзе; передавайте его в `GET /api/v1/orders/{id}` и в отмену |

В ответах `202`/`422`/`502` добавлены `code` и `error`. Исполнение и дальнейшие изменения приходят в строке `Orders` через REST или gRPC.

### Снятие заявки

`POST /api/v1/orders/{id}/cancel` принимает `id` шлюза или ключ строки `Orders`; снять можно активную заявку, выставленную через шлюз. Шлюз отправляет снятие в QUIK и отвечает после ответа QUIK (ожидание до 10 с). Ответ — заявка в том же формате, что при создании:

| Код | `code` | Значение |
|---|---|---|
| `200` | — | QUIK снял заявку, `State` = `Снята`. Если строка уже была снята — сама строка `Orders` |
| `409` | `CANCEL_REJECTED` | QUIK не снял заявку: она осталась активной или исполнилась (см. `State`, `Balance`) |
| `202` | `QUIK_ANSWER_PENDING` | QUIK не ответил за время ожидания; итог — через `GET /api/v1/orders/{id}` |
| `409` | — | Заявка не активна в QUIK или выставлена не через шлюз |

Изменение цены или количества: снять и создать новую заявку.

### State: состояние заявки

| `State` | Значение |
|---|---|
| `Активна` | Принята QUIK, есть неисполненный остаток `Balance` |
| `Исполнена` | Исполнена полностью |
| `Снята` | Снята или истёк срок |
| `Отклонена` | Отклонена QUIK, причина в `RejectReason` |
| `null` | QUIK ещё не ответил |

## Сделки

| REST / gRPC | Назначение | Возвращаемые данные | Право |
|---|---|---|---|
| `GET /api/v1/trades` | Сделки своей фирмы, новые первыми | Массив исходных строк QUIK `Trades` | `trades:read` |
| gRPC `trade.created` | Новые сделки своей фирмы за сегодня | `event.data_json` — исходный JSON строки `Trades` | `trades:read` |

Источник — таблица QUIK `quik_export2.public."Trades"`, как для заявок `Orders`: имена колонок, числа, строки и `null` передаются без изменений, шлюз ничего не добавляет. Каждая строка — одна сторона сделки; `FirmId` ограничен `quik_firm` токена (при пустом значении — кодом брокера). Основные колонки: `TradeNum`, `TradeDate`, `ClassCode`, `SecCode`, `OrderNum`, `Operation`, `Price`, `Qty`, `FirmId`, `Account`, `ClientCode`, `CPFirmId` (фирма контрагента).

```json
[{"TradeNum":11094,"TradeDate":"2026-10-06T00:00:00","ClassCode":"LIST_GBA","SecCode":"GBA02280810","OrderNum":22450,"Operation":"Купля","Price":99.00000000,"Qty":201,"FirmId":"2040","Account":"1-3101-2040","ClientCode":"Kalys","CPFirmId":"BAKAI2008"}]
```

Список принимает `limit` 1–1000 (по умолчанию 200) и `offset`; заголовки `X-Has-More` и `X-Next-Offset` задают продолжение. Ошибка БД QUIK — 503. gRPC не отправляет начальный список: загрузите его через REST; новые строки проверяются каждые две секунды, включая сделки по заявкам, поданным вне шлюза. Сделку с заявкой связывает `OrderNum`.

## Рыночные данные и стакан

Все методы и событие требуют `orders:read`.

| REST / gRPC | Назначение | Возвращаемые данные |
|---|---|---|
| `GET /api/v1/market-data` | Текущие торги | JSON-массив инструментов (32 поля, см. ниже); при недоступности источника — HTTP 503 |
| `GET /api/v1/market-data/{board}/{symbol}` | Один инструмент | Строка по `ClassCode` и `SecCode`; 404, если её нет за сегодня или класс не выбран |
| `GET /api/v1/quotes` | Котировки инструмента без участников | JSON-массив `{side, price, quantity, volume}` (см. ниже) |
| `GET /api/v1/orderbook` | Стаканы: спрос и предложение рынка (FIX) | `{source: "live", live, books: [OrderBook]}`; без доступных данных — `live: false`, `books: []`, `note` |
| gRPC `marketdata.tick` | Изменения строк `Params` | `event.data_json` — исходная строка, `event.removed` — строка исчезла |

Строка содержит только поля `ClassCode`, `SecCode`, `CouponValue`, `status`, `FaceUnit`, `SecShortName`, `SecFullName`, `ClassName`, `lotsize`, `tradingstatus`, `pricemin`, `pricemax`, `realminstep`, `bid`, `biddepth`, `offer`, `offerdepth`, `last`, `qty`, `time`, `open`, `high`, `low`, `prevprice`, `waprice`, `numtrades`, `voltoday`, `valtoday`, `accruedint`, `yield`, `nextcoupon`, `couponperiod` — из таблиц QUIK `Params`, `Securities` (по `ClassCode` + `SecCode`) и `Classes`. В `time` значимо только время: дата в нём фиктивная. Значения в исходном виде: числа JSON-числами с исходной точностью, строки и `null`. Разбирайте JSON с сохранением точности чисел. Отдаются только инструменты текущего торгового дня (по Бишкеку, UTC+6) из классов, выбранных администратором шлюза (если классы не выбраны — всех классов). Рыночные данные общие для всех брокеров.

```json
{"ClassCode":"LIST_GBA","SecCode":"GBA02270915","CouponValue":2.500000,"status":"торгуется","FaceUnit":"KGS","SecShortName":"ГКО-2 летние (GBA02270915)","SecFullName":"ГКО-2 летние (GBA02270915)","ClassName":"Листинговые:облигации","lotsize":1,"tradingstatus":"открыта","pricemin":86.00000000,"pricemax":100.00000000,"realminstep":null,"bid":100.00000000,"biddepth":16.00000000,"offer":null,"offerdepth":null,"last":95.00000000,"qty":15.00000000,"time":"1900-01-01T16:40:15","open":null,"high":100.00000000,"low":95.00000000,"prevprice":95.00000000,"waprice":95.40000000,"numtrades":3,"voltoday":125.0000,"valtoday":11925.0000,"accruedint":null,"yield":16.9200,"nextcoupon":"2027-01-31T00:00:00","couponperiod":184}
```

REST-фильтры: `?board=<ClassCode>&symbol=<SecCode>`, оба необязательны; `limit` (1–5000, по умолчанию 1000) и `offset`, продолжение — в заголовках `X-Has-More` и `X-Next-Offset`. Если источник недоступен, ответ — HTTP 503 с `{"error":"market data unavailable"}` и `Retry-After`; пустая успешная выборка — `[]`.

В gRPC снимка при подписке нет: загрузите текущие строки через REST и применяйте события по ключу `ClassCode` + `SecCode`. Таблица опрашивается раз в секунду; событие приходит только для изменившейся строки.

### Котировки

`GET /api/v1/quotes?board=<ClassCode>&symbol=<SecCode>` возвращает котировки одного инструмента: активные заявки (`State` = `Активна`) сегодняшнего торгового дня (по Бишкеку, UTC+6) всех участников рынка. `board` и `symbol` обязательны, без них — HTTP 400.

Участники не раскрываются. Котировка содержит только четыре поля: `side` (`BUY`/`SELL`), `price`, `quantity` (оставшееся количество в заявке) и `volume` = `price` × `quantity`. Номера заявок, фирмы, счета и коды клиентов не передаются. Числа — JSON-числа с исходной точностью; недоступное значение — `null`.

```json
[{"side":"BUY","price":100,"quantity":10,"volume":1000},{"side":"SELL","price":100.5,"quantity":4,"volume":402}]
```

`limit` 1–1000 (по умолчанию 200), `offset` 0–10 000 000; иначе HTTP 400. Порядок — от новых заявок к старым. Продолжение — заголовки `X-Has-More` и `X-Next-Offset`: следующую страницу запрашивайте с `offset` = `X-Next-Offset`, пока `X-Has-More` не станет `false`. Страницы не являются снимком: если заявки меняются между запросами, перечитайте список с первой страницы. Лимит частоты — операция `GetOrders`. Источник недоступен — HTTP 503.

`OrderBook` содержит только `symbol`, `security_id`, `board`, `currency`, `name`, `last`, `last_size`, `last_time`, `bid`, `bid_size`, `offer`, `offer_size`, `bids`, `offers`, `updated_at`. Массивы уровней в REST-стакане присутствуют всегда, в том числе пустые.

### Изменение контракта 26.10.2026

`GET /api/v1/market-data` и gRPC `marketdata.tick` переведены с FIX Market Data на таблицу QUIK `Params`. Вместо `{quotes: [MarketQuote]}` REST возвращает массив исходных строк; в gRPC строка передаётся в `data_json`, без `quotes`, `live` и `replace`, и начальный снимок при подписке больше не приходит. Фильтры `board`/`symbol` относятся к `ClassCode`/`SecCode`. Стакан `/api/v1/orderbook` не изменился.

В тот же день строка сокращена до 8 полей (`ClassCode`, `SecCode`, `CouponValue`, `status`, `FaceUnit`, `SecShortName`, `SecFullName`, `ClassName`); остальные колонки `Params`, включая `TradeDate`, больше не передаются. Отдаются только строки сегодняшнего торгового дня из классов, выбранных администратором (если классы не выбраны — всех классов).

02.11.2026 в конец строки добавлены 24 поля `Params`: условия заявки, рынок, итоги дня и данные облигаций. Прежние поля и их порядок не изменились. `TradeDate` по-прежнему не передаётся.

## Позиции

| REST / gRPC | Назначение | Возвращаемые данные | Право |
|---|---|---|---|
| `GET /api/v1/positions` | Позиции своей фирмы | `{cash: [...], instruments: [...]}`: исходные строки QUIK `MoneyLimits` и `DepoLimits` за последнюю дату | `positions:read` |
| gRPC `positions.updated` | Полные снимки позиций своей фирмы | `event.data_json` — тот же объект | `positions:read` |

`cash` — деньги, `instruments` — бумаги. Имена колонок, числа, строки и `null` не меняются; набор колонок задаёт QUIK. Фирма — `quik_firm` токена, при пустом значении — код брокера. gRPC отправляет полный снимок после `ready` и при изменении позиций (проверка раз в секунду). Каждый снимок полностью заменяет оба массива. При отсутствии позиций массивы пустые. Если источник QUIK недоступен, REST отвечает 503. REST-фильтров по клиенту или инструменту нет.
## gRPC: команды и сообщения

Один двунаправленный RPC: `/fixgateway.realtime.v1.RealtimeService/Stream`. Для всех четырёх событий используется этот путь.

Первое сообщение — `subscribe`, в течение 5 секунд после открытия потока:

```json
{"subscribe":{"event_types":["order.updated","trade.created","positions.updated","marketdata.tick"]}}
```

Пустой `event_types` выбирает все события, разрешённые токену. Повторный `subscribe` полностью заменяет список.

| Сообщение | Данные |
|---|---|
| Клиент: `subscribe.event_types` | Массив типов событий |
| Клиент: `ping.id` | ID проверки связи, до 128 байт |
| Сервер: `ready.event_types` | Подтверждённый список подписок |
| Сервер: `event.sequence` | `uint64`, общий счётчик процесса; не курсор возобновления |
| Сервер: `event.type` | Один из четырёх брокерских типов событий |
| Сервер: `event.data` | `google.protobuf.Struct`; поля описаны выше |
| Сервер: `event.occurred_at` | `google.protobuf.Timestamp`, время формирования события |
| Сервер: `pong.id` | ID из `ping`; сервер также отправляет пустой `pong` каждые 20 секунд |

Числа внутри `Struct` представлены как `double`; цены, суммы и количества остаются строками. В примерах используется JSON с protobuf-именами полей; стандартный ProtoJSON также использует `eventTypes` и `occurredAt`, а `sequence` кодирует строкой.

Права и токен перепроверяются каждые 5 секунд. Отзыв, истечение срока, смена прав или фирмы закрывают поток. Для токена без срока одно подключение ограничено 24 часами.

Пропущенные события не воспроизводятся. После переподключения обновите заявки и сделки через REST; позиции и рынок приходят начальными gRPC-снимками. Пропуски `sequence` допустимы из-за фильтрации событий.

Входящее сообщение — до 16 КиБ, исходящее — до 8 МиБ; очередь — 64 события на подписку. Переполнение очереди закрывает поток с `ResourceExhausted`. Создание и отмена заявок выполняются через REST.

## HMAC для REST и gRPC (необязательно)

По умолчанию `HMAC_REQUIRED=false`: достаточно Bearer-токена. При обязательной подписи передавайте `X-Timestamp`, `X-Nonce`, `X-Signature`; в gRPC — metadata с теми же именами в нижнем регистре. Если передан хотя бы один из них, нужны все три и подпись проверяется.

`timestamp` — Unix time в секундах, допустимое отклонение ±5 минут. `nonce` — уникальная строка 8–128 байт на запрос или открытие потока; повтор отклоняется в течение 10 минут в пределах токена.

```text
payload = timestamp + "\n" + nonce + "\n" + method + "\n" + path + "\n" + body
signature = hex(HMAC-SHA256(API-токен, payload))
```

REST: `method` — HTTP-метод, `path` — точный escaped path с исходной query-строкой, `body` — точные байты тела. gRPC: `method = POST`, `path = /fixgateway.realtime.v1.RealtimeService/Stream`, `body` — пустая строка. Для каждого переподключения используйте новый nonce.

## Ошибки

REST возвращает ошибки в общем формате: `success: false`, `code`, `message` и `error_code`; `data` — `null` или заявка. Справочник кодов — `GET /api/v1/errors`: `codes` (поле `code`) и `error_codes` (поле `error_code`, с операцией `order`/`cancel` и источником в QUIK). QUIK может прислать код, которого нет в справочнике; текст причины всегда в `message`.

| HTTP | `code` | Значение |
|---|---|---|
| `202` | `QUIK_ANSWER_PENDING` | QUIK не ответил за время ожидания; заявка в `data` не отменена |
| `400` | `VALIDATION_ERROR` | Неверный JSON, параметры, счёт, неизвестный инструмент |
| `401` | `UNAUTHORIZED` | Нет или недействителен токен; неверная подпись / повтор nonce |
| `403` | `FORBIDDEN` | Нет права, IP запрещён, требуется HTTPS или указана чужая фирма |
| `404` | `NOT_FOUND` | Объект отсутствует или принадлежит другой фирме |
| `409` | `CANCEL_REJECTED` / `CONFLICT` | QUIK не снял заявку; заявка не активна |
| `422` | `ORDER_REJECTED` / `TRADING_PAUSED` / `MAX_ORDER_QUANTITY` / `MAX_OPEN_ORDERS` | QUIK отклонил заявку (заявка в `data`) или торговое ограничение шлюза |
| `429` | `RATE_LIMITED` / `RESOURCE_EXHAUSTED` | Лимит запросов; пауза указана в `Retry-After` |
| `500` | `INTERNAL_ERROR` | Внутренняя ошибка |
| `502` | `ORDER_FAILED` / `BAD_GATEWAY` | Заявку не удалось передать в QUIK |
| `503` | `SERVICE_UNAVAILABLE` | Временная недоступность QUIK, авторизации, хранения или перегрузка |

Лимиты задаёт оператор для брокера и операций. Перед повтором создания после сетевой ошибки проверьте `GET /api/v1/orders`: каждый POST — новая заявка. `X-Request-ID` и `X-Trace-ID` — необязательные ID для поиска запроса.

| gRPC status | Значение |
|---|---|
| `Unauthenticated` | Токен, подпись или сессия недействительны |
| `PermissionDenied` | Нет права на событие или тип события неизвестен |
| `InvalidArgument` | Первое сообщение не `subscribe`, команда неизвестна или ID `ping` слишком длинный |
| `DeadlineExceeded` | Нет первой подписки за 5 секунд или клиент не принимает данные |
| `ResourceExhausted` | Лимит подключения, команды, размера сообщения или очереди; при ограничении операции — `RetryInfo` |
| `Unavailable` | Поток, авторизация или снимок позиций временно недоступны |
| `Internal` | Ошибка сериализации позиций |
