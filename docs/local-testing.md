# Изолированный локальный стенд

Из корня репозитория запустите Docker Desktop и выполните:

```powershell
docker compose -f deploy/docker-compose.local.yml up --build -d --wait --wait-timeout 180
```

Требуется современный Docker Compose с `dockerfile_inline` (2.17+). Сборка скачивает зависимости; gateway, PostgreSQL и FIX simulator используют внутреннюю Docker-сеть без исходящего доступа в LAN/Интернет. UI и фиксированный TCP bridge `access` подключены также к отдельной сети для публикации loopback-портов. Bridge передаёт HTTP, native gRPC и PostgreSQL без завершения TLS; mTLS проверяет сам gateway. Стенд имеет имя `fix-gateway-local`, собственные БД и сертификаты, отдельные порты. Штатный UAT Compose и его данные не используются. Не объединяйте эти Compose-файлы через несколько `-f` и не меняйте имя проекта.

Админка: http://localhost:25173 — `admin@localhost` / `admin123`.
Брокерское приложение: http://localhost:25174.
REST API / Swagger: http://localhost:28080/swagger.
Native mTLS gRPC: localhost:28443.
PostgreSQL: localhost:25432, БД `fix_gateway_local`, пользователь `gateway`, пароль `local-simulator-only`.
Все опубликованные порты привязаны к loopback.

Последовательность старта: PostgreSQL → штатные миграции → transactional simulator bootstrap → gateway. Bootstrap отключает все адаптеры, включая ARQA, и включает только два локальных FIX.4.4 simulator. Gateway не запускается до успешного завершения bootstrap. Дополнительно `ADAPTER_HOST_OVERRIDE=fixsimulator` и internal network исключают исходящее соединение к реальной бирже. QUIK HTTP origin заменён на loopback-заглушку; фоновые market-data/position sync выключены. Реальные QUIK справочники и рыночные данные здесь недоступны.

## Проверка и тестовая заявка

```powershell
Invoke-RestMethod http://localhost:28080/health
Invoke-RestMethod http://localhost:28080/ready
docker compose -f deploy/docker-compose.local.yml ps -a
node scripts/local-smoke.mjs
```

Smoke требует Node 22 и проверяет принадлежность endpoint изолированному проекту до записи данных. Он создаёт тестовых брокеров, счета и токены; проверяет идемпотентность, исполнение и сделки, отмену, FIX-отказ, изоляцию брокеров, поток SSE через mTLS gRPC, параллельную маршрутизацию через оба адаптера и запрет отключения последнего. В конце токены отзываются, отключённый для проверки адаптер включается обратно. Тестовые записи остаются в локальной БД для просмотра в интерфейсе. Эти же сценарии включены в CI.

`/ready` должен вернуть успешный ответ с доступным адаптером. В админке проверьте, что включены только `adapter-1` и `adapter-2`, а ARQA отключены. Bootstrap создаёт брокера `LOCAL_DEMO` и счёт `LOCAL_ACCOUNT`. В админке создайте для этого брокера токен с правом торговли и firm `LOCAL_FIRM`; сохраните выданный токен. В брокерском приложении укажите Gateway URL `http://localhost:25174` (same-origin proxy), добавьте токен и подключитесь. Для первой заявки используйте `SBER`, board `TQBR`, счёт `LOCAL_ACCOUNT`, client code `LOCAL_CLIENT`, BUY LIMIT, количество `1`, цену `100`. Simulator обрабатывает заявки локально; это не UAT биржи. Наблюдайте статус и сделки в брокерском приложении и админке. Повторный `client_order_id` используется для проверки идемпотентности через REST.

## Проверка устойчивости

После обновления образа gateway выполните `node scripts/local-reliability.mjs` из корня проекта. Тест разрешает работу только с проверенным изолированным Compose-проектом на порту 28080 и двумя simulator-адаптерами. Он создаёт 143 тестовые заявки BUY/SELL, проверяет торговлю при шквале опросов, отключает simulator, аварийно завершает gateway, восстанавливает обработку, затем отключает PostgreSQL и проверяет явный 503 и повтор с прежним ключом идемпотентности. Сверяется наличие единственной записи заявки и ORDER_SEND в БД; после FIX-восстановления проверяется отсутствие повторных исполнений.

Тест временно прерывает работу локального стенда. В `finally` восстанавливаются остановленные зависимости и отзывается тестовый токен; тестовые заявки сохраняются. Не запускайте одновременно со smoke-тестом или другим сценарием изменения адаптеров. Эти проверки не определяют гарантируемую пропускную способность UAT/биржи и не моделируют потерю диска БД или неопределённое подтверждение биржи.

Обработчик outbox пробуждается после подтверждённого сохранения заявки или отмены; периодическое чтение БД остаётся механизмом восстановления после потери сигнала и перезапуска. Уведомление в памяти никогда не заменяет постоянную очередь.

## Остановка и повторный запуск

```powershell
docker compose -f deploy/docker-compose.local.yml down
docker compose -f deploy/docker-compose.local.yml up --build -d --wait --wait-timeout 180
```

Данные сохраняются; bootstrap при повторном запуске вновь отключает ARQA. При обновлении миграций сначала остановите стенд командой `down`, затем запускайте `up`: это гарантирует выполнение bootstrap до нового gateway.

Для намеренного удаления только тестовых данных и development PKI:

```powershell
docker compose -f deploy/docker-compose.local.yml down -v
```

Development сертификаты действуют 30 дней; после истечения пересоздайте тестовый PKI. Команда `down -v` также удаляет тестовую БД. Пароли этого стенда предназначены для локальной разработки.
