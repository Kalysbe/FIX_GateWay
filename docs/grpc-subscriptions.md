# Подписки брокеров и окно gRPC

В админке раздел **gRPC · Подписки** (`/grpc`) показывает активные подключения,
брокера, события и пути соответствующих данных. Отображаются нативные gRPC-клиенты,
включая внешние системы с админским JWT; подключения нашей браузерной админки
скрыты. Изменения приходят сразу через административный
поток; каждые 10 секунд выполняется дополнительная сверка снимка. Права просмотра:
SUPER_ADMIN, ADMIN, OPERATOR, AUDITOR. Снимок процесса не является историей
соединений и не объединяет подключения других экземпляров gateway.

REST: `GET /api/v1/admin/grpc/connections`. Ответ содержит `instance_id`,
`revision`, `connections`; токены и подписи в ответ не попадают. Поток отправляет
`subscriptions.updated` при подключении, смене событий и отключении. Этот тип
события недоступен брокерам и READ_ONLY.

## Подключение брокера

Используется тот же RPC `/fixgateway.realtime.v1.RealtimeService/Stream` и
тот же protobuf-контракт. По умолчанию: VPN + TLS + API-токен, без клиентского
сертификата и HMAC. Сертификат сервера проверяется через системное доверие или
CA оператора. Метаданные:

```text
authorization: Bearer <API-токен брокера>
x-client-type: broker
```

`x-client-type` необязателен для выданных шлюзом API-токенов: шлюз отличает их
от админского JWT автоматически. Явное значение `broker` также поддерживается.

При отдельно включённом `GRPC_MTLS_REQUIRED=true` нужен клиентский сертификат
с назначением clientAuth и его закрытый ключ.

При обязательном HMAC также нужны `x-timestamp`, `x-nonce`, `x-signature`.
Подпись вычисляется ключом API-токена по обычному `BuildHMACPayload`:
Unix timestamp, nonce, `POST`, полный RPC-путь выше, пустое тело; поля разделяются
переводом строки. Подписывается открытие потока, дальнейшие команды защищены TLS.
При переподключении нужен новый nonce. Без HMAC-настроек подписанные подключения
также проверяются, если переданы соответствующие метаданные.

Первым сообщением отправить:

```json
{"subscribe":{"event_types":["order.updated","trade.created","marketdata.tick","positions.updated"]}}
```

`order.updated` требует `orders:read`, `trade.created` — `trades:read`,
`marketdata.tick` — `orders:read`, `positions.updated` — `positions:read`. Строки заявок (`Orders`) и сделок (`Trades`) доставляются только
своей фирме; строки текущих торгов (`Params`) общие. Пустой список выбирает все разрешённые события.
Повторный Subscribe полностью заменяет список. Административные события брокеру
запрещены. Пути в окне — соответствующие источники данных (`/api/v1/orders`,
`/api/v1/trades`, `/api/v1/market-data`), а не отдельные RPC.

### REST-источники брокерских событий

Все четыре брокерских события имеют REST-методы и схемы в `/broker-swagger`:

- `order.updated` → `GET /api/v1/orders` и `GET /api/v1/orders/{id}` (`orders:read`).
- `trade.created` → `GET /api/v1/trades` (`trades:read`), новая строка QUIK `Trades` своей фирмы за сегодня в `data_json`.
- `positions.updated` → `GET /api/v1/positions` (`positions:read`).
- `marketdata.tick` → `GET /api/v1/market-data` и `GET /api/v1/market-data/{board}/{symbol}` (`orders:read`), строка текущих торгов (8 полей из QUIK `Params`/`Securities`/`Classes`) в `data_json`.

Успешный рыночный REST-снимок содержит только `quotes`.
Поля котировки совпадают с gRPC: стакан, цены OHLC, средневзвешенная цена,
объём, оборот, торговый статус и время обновления. ID адаптера, ID FIX-запроса,
сырые FIX-поля и диагностика подписки исключены. Недоступность потока в REST
обозначается HTTP 503 с `Retry-After`; пустая доступная выборка — HTTP 200 с `quotes: []`.
Без параметров выдаются все подписанные инструменты;
существующие REST-фильтры `symbol` и `board` ограничивают только ответ.
`GET /api/v1/orderbook` остаётся доступен как компактная выдача стаканов.
Полный gRPC-снимок также содержит `live` и `replace: true`; изменения котировок
без этих флагов не меняют ранее полученную доступность потока.
Эти признаки нужны для обработки потока сообщений и не добавляются в REST GET.

REST возвращает текущие данные, gRPC — события изменений. Списки заявок и сделок
содержат последние 100 записей; REST не воспроизводит пропущенные события gRPC.
Административные события сохраняют административные права и не входят в Broker API.

Используются статус и срок API-токена, статус брокера, IP-whitelist по адресу
нативного gRPC-клиента. Метаданные с чужим IP не принимаются. Проверка повторяется
каждые 5 секунд; отзыв токена и изменение прав закрывают поток. Токен без срока
ограничивает одно подключение 24 часами, после чего нужно подключиться заново.
Действуют ограничения очереди и потребителя из [realtime-grpc.md](realtime-grpc.md).
Пропущенные события не воспроизводятся: после переподключения обновить REST-снимок.

### Позиции по деньгам и инструментам

После `ready` подписка `positions.updated` сразу отправляет полный снимок позиций,
а затем новый полный снимок при каждом изменении. По поручению пользователя
02.11.2026 источник — таблицы QUIK `MoneyLimits` (`cash`) и `DepoLimits`
(`instruments`), строки за последнюю `LoadDate` каждой; изменения проверяются раз в
секунду. FIX-запросы позиций (`35=AN`) шлюз больше не отправляет.

`event.data_json` содержит `{"cash":[...],"instruments":[...]}`: исходные строки, как в
`GET /api/v1/positions`; `event.data` пуст, чтобы не терять точность чисел. Клиент
полностью заменяет прежние массивы, включая пустые, чтобы удалённые позиции исчезали.
Фильтр фирмы определяется `quik_firm` токена, при пустом значении — кодом брокера,
как в REST. Клиентские метаданные не меняют фильтр. Отзыв токена,
смена фирмы или прав закрывают поток; после переподключения приходит новый снимок.

Браузерная брокерская панель продолжает использовать REST. Для новой подписки
нужен нативный gRPC-клиент; браузерный административный мост не принимает API-токены
брокеров.
