# Локальная проверка QUIK 172.23.10.84 — 13 октября 2026

Продовый FIX_GateWay на `172.23.10.96` использовал справочник с классами `CROSSRATE`, `QME_A1`, `QuikREPO_A1`. Оба FIX-адаптера были ONLINE, но рыночные данные: `RETRYING`, подтверждено `0/11`. Эти 11 инструментов отсутствовали в актуальном справочнике `.84`.

## Проверка с локального компьютера

Порты `.84:15101` и `:15102` доступны по TCP. Прямой FIX-тест выполнялся на `.84:15102` с существующими параметрами `FIX.4.2`, `TEST → QUIK` и действующей политикой сброса при Logon. Пользователь разрешил временно отключить продовый `quik-fix-2`, чтобы избежать конкурирующего входа с тем же CompID. Основной адаптер оставался подключён. После каждого короткого теста второй адаптер восстановлен и проверен ONLINE.

Диагностический клиент использовал адаптер проекта, отдельное временное хранилище сессии и только запросы справочника/рыночных данных; подключения к базе или обработчика отправки торговых заявок у клиента нет.

Свежий ответ `.84` содержит ровно 19 инструментов:

| Класс | Инструментов | Подтверждено подписок |
| --- | ---: | ---: |
| QME_MTL | 13 | 13 |
| LIST_GBA | 3 | 3 |
| LIST_GD | 3 | 3 |
| Всего | 19 | 19 |

С этим справочником получены 19 ответов `35=X`, состояние `ACTIVE`, подтверждено `19/19`. Подтверждение включает настоящий пустой стакан и не означает, что по каждому инструменту сейчас открыты торги или есть цены/заявки.

Проверка трёх инструментов из сохранённого продового справочника воспроизвела исходную ошибку непосредственно на `.84:15102`:

| Класс | Код инструмента | Ответ `35=Y` |
| --- | --- | --- |
| CROSSRATE | EUR | Unknown ExDestination [CROSSRATE] (reason=0) |
| QME_A1 | KG0106166315 | Unknown ExDestination [QME_A1] (reason=0) |
| QuikREPO_A1 | KG0102222121 | Unknown ExDestination [QuikREPO_A1] (reason=0) |

Это подтверждает устаревший справочник как причину отказов. Автоматическая подписка перечитывала локальную БД каждые пять секунд, но загрузка справочника с QUIK выполнялась лишь при запуске.

## Применённое восстановление на проде

Штатный `POST /api/v1/admin/instruments/sync` на `.96` обновил справочник через текущий `quik-fix-1`. Без перезапуска шлюза подписка стала `ACTIVE`, подтверждено `19/19`, ошибка исчезла. Новые подключения по-прежнему используют `.84`.

Продовая версия старого парсера дополнительно создала семь записей `UNKNOWN` из названий инструментов; они исключались из FIX-подписки. В отдельном согласованном развёртывании ниже исправлены кодировка и разбор групп справочника. Автоматическое обновление справочника и исправление отписок остаются только в локальном коде.

## Исправление кириллицы на проде

Символы `�` в таблице поступали уже в JSON API: QUIK передаёт часть текстовых полей в Windows-1251, а backend обрабатывал их как UTF-8. 13 октября 2026 по разрешению пользователя на `.96` развёрнут узкий патч декодирования текста и разбора группы `311`/`55`. Шрифт и frontend не менялись. Остальные локальные изменения в этот выпуск не вошли.

Перед коротким перезапуском backend сохранены исходники и предыдущий образ; очередь outbox была пустой. После запуска readiness подтвердил два доступных адаптера и отсутствие ожидающих событий outbox/inbox. Оба подключения `.84:15101` и `.84:15102` — `ONLINE`, подписка через `quik-fix-2` — `ACTIVE`, подтверждено `19/19`. В активном справочнике ровно 19 инструментов, записей `UNKNOWN` нет.

Проверка API обнаружила десять котировок с кириллицей и ни одного символа U+FFFD. Примеры: `ГКО-2 летние (GBA02270915)` и `Сертификат ЗС Кыргызалтын, 1 гр`. Перед развёртыванием тесты ARQA и сборка именно этого узкого патча прошли в отдельной копии backend.

Результаты проверки: `output/encoding-fix-2026-10-13/production-verification.json`. Резервная копия на `.96`: `/home/nysh/fix_gw/.deploy-tmp/encoding-backup-20261013T063449Z`; предыдущий образ: `deploy-gateway:encoding-before-20261013t063449z`.

## Исправления в локальном коде

- Справочник обновляется периодически, после смены источника котировок и при `Unknown ExDestination`; пустой ответ/ошибка не затирают действующий справочник, повторные попытки ограничены по частоте.
- Источник справочника выбирается с учётом владельца подписки и приоритетов, вместо случайного порядка обхода адаптеров.
- Поля `311` и `55` одного инструмента больше не создают дубликат с названием вместо SecurityID. Текст Windows-1251 декодируется корректно.
- Отписка сохраняет код инструмента и класс. До исправления сервер отвергал 19 отписок с `NoRelatedSym dont match real size of valid InstrmtMDReqGrps`; повторный тест с исправлением выполнил 19 отписок без этого отказа.

Проверка: `go test -mod=readonly ./...` для всего backend прошла; прямой локальный тест `.84:15102` с исправленным адаптером прошёл. Код диагностики не отправлял `35=D`, `35=F`, `35=G`.
