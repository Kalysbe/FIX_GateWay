# Проверка безопасности FIX Gateway — 1 октября 2026

## Статус после исправлений

Шесть подтверждённых находок ниже исправлены, тесты воспроизведения преобразованы в регрессионные тесты защиты. Дополнительно закрыты риски отзыва административных сессий и блокировки рассылки медленным клиентом; исправлены ошибки go vet, исходного интеграционного теста и HTTP Hijack в обёртке метрик. Проверяется рабочая копия, включая ранее существовавшие незакоммиченные изменения.

- События фильтруются по роли, неизвестные типы запрещены. READ_ONLY получает marketdata, но не obs.event. У каждой gRPC-сессии ограниченная очередь 64 сообщения, write timeout 5 секунд, heartbeat и предел 1024 подписок. Переполненная очередь закрывает соединение без блокировки producer.
- API логируется независимо от Host, Origin, Referer и X-Forwarded-Host. Ticket и URL-encoded названия секретных query-параметров скрываются.
- HMAC включает точный escaped path + raw query; неполные заголовки отклоняются. Nonce изолированы по токенам и хранятся 10 минут. Кэш остаётся локальным процессу: для нескольких реплик/перезапуска необходим общий replay-store.
- JWT требует exp, iat, uid/sub и допустимую роль. HTTP проверяет актуальные status/role/revision пользователя по БД. Новая миграция 000018 обновляет revision при изменении пароля, роли, статуса или email, включая прямой SQL. WS-ticket удалён вместе с WebSocket. Активный gRPC-поток перепроверяет сессию каждые 5 секунд (DB timeout 2 секунды), закрывается при отзыве или истечении JWT.
- Админский JWT перенесён из localStorage в sessionStorage; прежние persistent credentials удаляются. Это уменьшает срок хранения, но не защищает токен от выполняющегося XSS. Эксплуатируемой XSS аудит не установил.
- HTTP ReadTimeout — 30 секунд. Метки Prometheus используют зарегистрированный маршрут и ограниченный набор методов; произвольные URL не создают новые series.
- Минимальная версия и Docker builder — Go 1.26.7, x/crypto — v0.56.0. gRPC закреплён на стабильной v1.83.2 с исправлением GO-2026-6443; сканирование повторено после замены версии.

Проверки после исправлений: `go test -race -tags integration ./...` с обеими одноразовыми БД (security и исходный order-idempotency тест), `go vet -tags integration ./...`, обе frontend-сборки. Собраны Docker targets gateway/devcerts; отдельный тестовый gateway стартовал с mTLS и ответил health=ok. Повторный запуск генератора проверил существующие сертификаты. Compose-конфигурация валидна. Source govulncheck: 0 достижимых уязвимостей, 1 предупреждение в требуемом модуле без найденного вызова. Дополнительно проверены реальный mTLS gRPC и его SSE-адаптер, двусторонний ping/pong и half-close, роль READ_ONLY, отказ без клиентского сертификата/с чужим CA/неверным hostname, отключение действующего потока после отзыва сессии, отзыв JWT после смены password_hash без ручного обновления updated_at и отключение медленного consumer.

**Совместимость:** после обновления требуется повторный вход администраторов. HMAC-клиенты с query обязаны подписывать полный request-target; запросы без query совместимы. Потребуется применить миграцию 000018 (gateway выполняет миграции при старте). Работающие контейнеры не перезапускались, изменения ещё не развёрнуты. По уточнению пользователя реализован gRPC Bidirectional Streaming / Protobuf / TLS 1.3 и mTLS по умолчанию. WebSocket удалён; браузер использует SSE-адаптер к этому же gRPC-потоку. Конфигурация и ограничения: [realtime-grpc.md](realtime-grpc.md).

Ниже сохранён первоначальный аудит как история найденных проблем; его формулировки описывают состояние до исправлений.

## Подтверждённые результаты

1. **Высокий приоритет: обход прав аудита через WebSocket.** `internal/api/ws.go` выдаёт ticket через `adminRO`, а `handleWS` отбрасывает principal после Consume. `internal/realtime/hub.go` отправляет каждому клиенту все события. `internal/observability/pipeline.go:161` публикует `obs.event`, включая сообщения, IP, broker_id и request_id. В локальном WebSocket-тесте READ_ONLY получил событие аудита, хотя RolesAudit исключает эту роль. Исправление: хранить principal на соединении и фильтровать события по тем же правам, что у HTTP; проверять актуальность сессии.

2. **Средний приоритет: клиент может отключить HTTP-журнал запроса.** `internal/observability/http.go:80` пропускает логирование при IsInternalUIRequest. Проверка доверяет Host, X-Forwarded-Host, Origin и Referer. Тест подтверждает: запрос внешнего клиента к `/api/v1/orders` с `X-Forwarded-Host: localhost:5173` становится «внутренним». Предустановленные localhost-hosts присутствуют независимо от APP_ENV. Это обходит HTTP-логирование, но не все отдельные бизнес-/auth-/audit-события. Исправление: не исключать защищённые API по клиентским заголовкам; forwarded-заголовки принимать только от доверенного proxy.

3. **Средний приоритет: query-параметры не защищены HMAC.** `internal/api/middleware.go:277` подписывает r.URL.Path, без RawQuery. Тест изменяет параметры GET-запроса, сохраняя исходную подпись, и проверка проходит. Изменение тела запроса и немедленный повтор nonce отклоняются. Исправление: согласовать с клиентами канонизацию и подписывать полный request-target с query. Это нарушение целостности подписанного запроса, не самостоятельный обход Bearer/HTTPS.

4. **Низкий приоритет: ticket отсутствует в маскировании query.** `RedactQuery("ticket=audit-sensitive-ticket")` сохраняет значение. HTTPMiddleware использует этот результат для QueryParams. Реальное сохранение ticket зависит от прохождения middleware и завершения WS-соединения; ticket одноразовый и живёт 30 секунд, успешное подключение уже расходует его. Исправление: маскировать ticket и URL-encoded имена секретных параметров, отключить запись credentials в access logs proxy.

5. **Низкий приоритет: неполный optional HMAC принимается.** При HMACRequired=false заголовок X-Signature без X-Timestamp/X-Nonce приводит к успешному возврату verifyOptionalHMAC. При обязательном HMAC отсутствие заголовков отклоняется. Исправление: если присутствует любой HMAC-заголовок, требовать полный корректный набор. Это не обход production-режима с HMACRequired=true.

6. **Низкий приоритет: JWT без exp принимается парсером.** Подтверждено тестом с JWT, подписанным тестовым ключом. Штатная выдача выставляет exp, истёкший JWT и неверный ключ отклоняются. Для эксплуатации требуется валидная подпись; это не возможность внешнему клиенту подделать JWT. Исправление: jwt.WithExpirationRequired(), обязательные uid/sub, согласованные claims.

## Дополнительные риски по коду

- `adminAuth` проверяет только подпись/claims и не сверяет статус пользователя или текущую роль с БД. Штатный JWT живёт 12 часов: отключение пользователя/смена роли не прекращают доступ уже выданного JWT до exp. Добавить отзыв/версию сессии и проверку статуса. Динамический сценарий отключения администратора не выполнялся.
- Hub.Broadcast последовательно пишет клиентам под RLock без write deadline; read loop WS не имеет срока жизни. Медленный клиент может задерживать рассылку и связанные HTTP-обработчики. Нагрузочная эксплуатация не выполнялась; добавить очереди/таймауты/ограничения подключений.
- API имеет лимит тела 1 MiB и ReadHeaderTimeout, но у http.Server отсутствует ReadTimeout. Проверить защиту от медленной отправки тела на gateway и proxy. DoS на работающем сервисе не запускался.
- Админский JWT хранится в localStorage; XSS получает доступ к нему. Наличие эксплуатируемой XSS не установлено.
- Production Validate есть, но default APP_ENV=development. Compose привязан к loopback и содержит dev-секреты; перед внешней публикацией требуется явно настроить production и HTTPS/HMAC. Настоящие значения .env не выводились.

- Security-интеграционные тесты: PASS с `-race`, отдельный временный PostgreSQL, все миграции проекта. Чтение чужой заявки → 404; отмена чужой заявки → 400, заявка сохранила NEW; создание с READ_ONLY → 403; expired/revoked → 401; whitelist без разрешённого IP → 403.
- HMAC: правильная подпись принимается, изменённое тело и повтор nonce отклоняются. HTTPS: X-Forwarded-Proto от недоверенного клиента не обходит requireHTTPS. READ_ONLY не проходит adminWrite.
- Локальный работающий сервис 127.0.0.1:8080: /health → 200; admin dashboard/users, broker orders без токена → 401; неверный JWT со spoofed XFF → 401; WS с JWT в query → 401. Запросы не отправляли заявки и не меняли бизнес-данные; могли создать штатные auth/HTTP-логи.
- `npm audit --json`: frontend — 0 известных уязвимостей (193 зависимости), broker-app — 0 (185). Это не проверка XSS и не гарантия отсутствия неизвестных CVE.
- `go vet ./...`: FAIL на существующем `internal/observability/store.go:435` (self-assignment n.Title = n.Title).
- Общий запуск с `-tags integration` блокируется существующим `internal/api/integration_test.go:65`: unused acc. Для security-прогона использован Go overlay, временно заменяющий только этот тест пустым package api_test. Исходный файл сохранён.

## Зависимости и версии сборки

`go.mod` задаёт минимальный Go 1.26.1, Dockerfile — плавающий `golang:1.26-alpine`. Source govulncheck на Go 1.26.1 нашёл 15 достижимых предупреждений стандартной библиотеки. Это результат для минимальной версии, не для работающего контейнера.

Метаданные бинарника работающего `fix_gateway-gateway-1` подтверждают Go 1.26.7. Binary govulncheck сообщил GO-2026-6354, GO-2026-6355 и GO-2026-5932 в x/crypto v0.55.0; бинарник собран с `-s -w`, поэтому результат требует сопоставления с source-анализом и не доказывает эксплуатацию SSH/OpenPGP в gateway. x/crypto/ssh исправлен в v0.56.0: [GO-2026-6355](https://pkg.go.dev/vuln/GO-2026-6355), [GO-2026-6354](https://pkg.go.dev/vuln/GO-2026-6354). Исправление stdlib net/url для ветки 1.26 — 1.26.6: [GO-2026-6218](https://pkg.go.dev/vuln/GO-2026-6218).

Финальный source govulncheck на Go 1.26.7: **0 достижимых уязвимостей**, 0 в импортированных пакетах и 3 в требуемых модулях без установленного вызова уязвимого кода. Предупреждения binary-сканера не включены в подтверждённые эксплуатируемые находки. Рекомендация: поднять минимальную версию Go, обновить x/crypto и фиксировать проверенную версию builder в CI.
