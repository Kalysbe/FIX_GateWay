# ЧАСТЬ 1. АУДИТОРСКИЙ ОТЧЁТ

## 1.1 Архитектура (кратко)
- **Приём заявки.** REST `POST /api/v1/orders` → `orders.Service.Create` → в одной транзакции `orders`, `order_events` и `outbox_events` → `outbox/worker.go` → `arqa.Adapter.SendOrder` (quickfixgo).
- **Входящие сообщения.** `fixaudit` (JSONL с fsync) → `executioninbox` (файл с fsync) → `api.Server.OnExecution` → `tradeledger.RecordFIX` → `orders.ApplyExecutionReport` → `realtime.Hub`.
- **Реальное время.** gRPC `grpcstream`; админка получает события через SSE-мост `api/stream.go`.
- **Текущие заявки.** `quikexport` читает `quik_export2.public."Orders"` (только чтение; лента опрашивает таблицу раз в 2 с).
- **Сделки.** Реестр `trades` / `trade_sides` / `trade_reports`, ежеминутная сверка с QUIK API, внутренние тревоги.

## 1.2 Что сделано хорошо
- **Правила AGENTS.md для `Orders` выполнены:**
  - строки передаются как есть (`row_to_json` + `json.RawMessage`);
  - фильтр по FirmId применяется в SQL до пагинации;
  - отдельный пул только для чтения;
  - в gRPC `data_json` + `removed` в конверте события;
  - локальные заявки не подставляются вместо `Orders`.
- **Реестр сделок:** одна BUY и одна SELL на сделку, архив исходных отчётов с sha256, вторая сторона не достраивается.
- **Надёжная доставка:** transactional outbox, отметка о попытке отправки (send fence), квитанции inbox, идемпотентность по ExecID.
- **Безопасность:**
  - токены хранятся как HMAC с pepper;
  - маскирование 554/925/96 в журнале;
  - production nginx с CSP и закрытыми `/metrics` и `/swagger`;
  - контейнеры read-only, секреты через `*_FILE`.
- **Код:** SQL-инъекций и утечек горутин не найдено; TODO/FIXME нет; CI на GitHub с `-race`, govulncheck и `npm audit`.

### СРЕДНИЕ
- **Ядро бэкенда:**
  - `LinkExecution` после фиксации транзакции может навсегда потеряться при повторе (`server.go:1723`);
  - повтор `client_order_id` с другими параметрами возвращает старую заявку без сравнения (`orders/store.go:124`);
  - средняя цена считается от `filled+lastQty`, а объём от CumQty (`store.go:509`);
  - `_, _ = tx.Exec` в транзакции (`store.go:553`);
  - дрейф счётчика активных заявок и утечка `pendingRaw` (`session_app.go:119`);
  - fsync под общим мьютексом, в том числе для heartbeat;
  - нет таймаутов у тика outbox, `checkAll` и `WriteTimeout` HTTP.
- **Реестр сделок:** сверка каждую минуту загружает всю историю, жёсткий предел 200 000 записей (`tradeledger/sync.go:32`), нет индекса `trade_reports.status`.
- **Безопасность:**
  - SSRF через `base_url` QUIK API (роль OPERATOR, редиректы, DNS не проверяется) (`quikapi/url.go:57`);
  - пробелы в журнале действий администраторов (whitelist, адаптеры, `patchToken` без значений до/после);
  - HMAC и mTLS по умолчанию выключены;
  - общие слоты конкурентности выделяются до аутентификации.
- **Дашборд** целиком отдаёт 503 без QUIK и сам пересчитывает `State`, что спорно с точки зрения AGENTS.md.
- **Документация и контракты:**
  - `broker-openapi.yaml` устарел (обещает 100 заявок, uuid, `OrderDetailResponse`);
  - `architecture.md` противоречит `production-hardening` (stateless или одна реплика);
  - `reconciliation.md` и `broker-api-guide.md` устарели;
  - хосты и БД QUIK расходятся: `.84`/`.85`, `quik_export`/`quik_export2`.
- **`realtime.pb.go`** собран не штатным скриптом (protoc v6.31 против Debian protoc).
