2.Формат запросов и ответов

  • Параметры и поля, обязательные для заполнения, отмечены символом «*».
  • Поля, входящие во вложенный объект или в элемент массива, отмечены символом «→».

2.1Авторизация

Bearer-токен в заголовке Authorization. Токен определяет брокера и FirmId QUIK. Фильтр по фирме применяется на стороне шлюза и параметрами запроса не расширяется.

2.2Формат ответа

application/json; charset=utf-8. Тело запроса разбирается строго: неизвестное поле — 400. Все методы, включая /health, отвечают в едином конверте:

НаименованиеТипКомментарий
success*логический«true» только для HTTP 200 и 201. Ответ 202 (QUIK ещё не ответил) приходит со значением «false»
code*строка«OK» или код ошибки, см. п. 8.1
message*строкаПричина ошибки. При успехе — null
error_code*числоЧисловой код причины от QUIK при отказе в заявке или снятии, см. п. 8.2. В остальных случаях — null
data*объект, массивРезультат: объект, массив строк QUIK или null. При ошибке, как правило, null. Заявка в data возвращается, если ответ касается её состояния в QUIK (раздел 5)
pageчислоТолько у списков. Номер страницы, с 1
limitчислоТолько у списков. Строк на странице
totalчислоТолько у списков. Строк по запросу всего, на всех страницах. Последняя страница — page × limit ≥ total

Ветвление — по code; message — человекочитаемый текст QUIK или шлюза, его формулировка не стабильна.

Даты и время — по времени КФБ (UTC+6), часовой пояс не указывается: дата — «17.11.2026», время суток — «16:40:15», дата и время — «17.11.2026 15:54:45». Параметры date, from и to принимаются в том же виде.

2.3Отслеживание изменений

В REST API изменения отслеживаются опросом. Строка Orders появляется в QUIK обычно не позже 0,5 с после отправки заявки.

ДанныеКомментарий
Свои заявкиGET /api/v1/orders/{id} для заявок в ожидании ответа QUIK; GET /api/v1/orders/active — книга заявок фирмы
СделкиПервая страница GET /api/v1/trades?date=<сегодня>; новые строки — с номером TradeNum больше последнего обработанного
ПозицииGET /api/v1/positions/moneylimits и /depolimits, полный снимок
РынокGET /api/v1/market-data, GET /api/v1/orderbook, GET /api/v1/market-data/trades

Частота опроса ограничена лимитами п. 8.4.

3.Служебные методы

Проверка работы шлюза. Токен не требуется. Связь шлюза с QUIK метод не проверяет.

Пример запроса:

Пример ответа:

  "success": true,
  "code": "OK",

  "error_code": null,
  "data": {

  }
}

5.Заявки

Создание и снятие синхронны: шлюз отвечает после ответа QUIK. Состояние заявок читается из Orders по FirmId токена.

5.1POST /api/v1/orders

Выставление заявки. Имена полей — колонки Orders. Таймаут ожидания ответа QUIK — 10 с.

Список поддерживаемых полей запроса:

НаименованиеТипКомментарий
ClassCode*строкаКод класса. Значение ClassCode из GET /api/v1/instruments
SecCode*строкаКод инструмента. Значение SecCode из GET /api/v1/instruments
Operation*строкаНаправление. Возможные значения:
  • «Купля»;
  • «Продажа»
PriceчислоЦена, больше 0. С ценой заявка лимитная, без цены — рыночная
Qty*числоКоличество, больше 0
Account*строкаТорговый счёт. Значение TrdAccId из GET /api/v1/accounts
ClientCode*строкаКод клиента

Срок действия — день. FirmId берётся из токена; FirmId в теле — 400. Пара ClassCode + SecCode, которой нет в GET /api/v1/instruments (в том числе класс, не выбранный биржей), — 400.

Пример запроса:

curl -X POST http://<адрес-шлюза>/api/v1/orders \
  -H "Authorization: Bearer <API-токен>" \
  -H "Content-Type: application/json" \
  -d '{
    "ClassCode": "LIST_GBA",
    "SecCode": "GBA02270915",
    "Operation": "Купля",
    "Price": 99.5,
    "Qty": 1,
    "Account": "1-0001-001",
    "ClientCode": "Иван"
  }'

Список полей заявки в ответе:

НаименованиеТипКомментарий
idстрокаИдентификатор заявки в шлюзе. По нему заявка находится и снимается, пока OrderNum неизвестен
OrderNumчислоНомер заявки в QUIK. У отклонённой заявки — null
StateстрокаСостояние заявки. Возможные значения:

5.4GET /api/v1/orders/{id}

Строка Orders одной заявки.

Список поддерживаемых параметров:

8.3Торговые ограничения

Pre-trade ограничения шлюза, HTTP 422. Заявка не создаётся и в QUIK не передаётся.

codeКомментарий
TRADING_PAUSEDПриём новых заявок приостановлен оператором шлюза
MAX_ORDER_QUANTITYКоличество больше лимита на одну заявку
MAX_OPEN_ORDERSДостигнут лимит одновременно активных заявок

В message указывается, чьё ограничение сработало: «общее ограничение» — для всех брокеров, «ограничение брокера» — только для фирмы токена.

Пример ответа:

{
  "success": false,
  "code": "TRADING_PAUSED",
  "message": "Приём новых заявок приостановлен (общее ограничение)",
  "error_code": null,
  "data": null
}

8.4Лимиты запросов

По умолчанию — 100 запросов и 20 заявок в секунду на брокера; биржа может установить брокеру другие значения. При превышении — 429, пауза до повтора в секундах — в заголовке Retry-After.

8.5Повтор запросов

POST /api/v1/orders не идемпотентен: повтор создаёт новую заявку. После таймаута, сетевой ошибки, 502 или 503 заявка сначала ищется в GET /api/v1/orders и отправляется повторно, только если её там нет.
