# Заявки из БД QUIK

Источник — `quik_export2.public."Orders"` на `192.168.0.89:5432`.
Подключение задаётся в `QUIK_EXPORT_DATABASE_URL`; каждая сессия только для
чтения. Миграции Gateway к этой БД не применяются.

По решению пользователя от 22.10.2026 строки передаются как результат
`row_to_json(o)`: все столбцы с оригинальными названиями и значениями, включая
неизвестные Gateway поля и `null`. `OrderNum`, `Qty`, `Price` и другие числовые
поля остаются JSON-числами с исходной точностью. `Operation`, `State`, даты и
время не переименовываются и не переводятся. Нет добавленных `id`, `source`,
`status`, `filled_quantity`, `gateway_order_id`, истории, исполнений или trace.
Админка показывает только поля строки БД; числа отображаются без округления.

`GET /api/v1/orders` и `GET /api/v1/admin/orders` возвращают массив строк.
`GET /api/v1/orders/{id}` и admin-вариант возвращают одну исходную строку.
Внутренний ключ URL `quik-20261022-LIST_GBA-22455` содержит дату, класс и номер,
но не добавляется в ответ. Локальный UUID тоже разрешается в настоящий QUIK
OrderID, если соответствующая строка ещё есть в текущей таблице. Иначе — 404.

Для брокера SQL ограничен `FirmId`, равным `quik_firm` авторизованного токена,
при пустом значении — кодом брокера. Клиентские фильтры не расширяют доступ.
Admin может задать `firm_id` или `broker_id` (код выбранного брокера).

`limit` — 1–1000, по умолчанию 200; `offset` — 0–10000000.
Пагинация вынесена из тела ответа в HTTP-заголовки `X-Has-More` и
`X-Next-Offset`. Админка читает все страницы. Порядок — дата и номер по
убыванию, затем класс. При одновременном изменении живой таблицы следует
обновить список с первой страницы.

`order.updated` отслеживает всю таблицу раз в две секунды, включая внешние
заявки. В native gRPC исходная строка JSON находится в `Event.data_json`:
обычный `google.protobuf.Struct` хранит числа как double и для этой задачи
не используется. Клиенту следует разобрать JSON с сохранением точности чисел.
`Event.data` для этих событий пуст. Удаление строки обозначается
`Event.removed=true`; сам исходный JSON не меняется. Browser SSE передаёт
строку в `data`, а `removed` — рядом с `type`, вне строки заявки. Начальный
набор загружается через REST.

Ошибка чтения даёт 503 без подстановки локальных данных. Фоновая ошибка не
считается пустой таблицей и не порождает удалений. Исчезновение строки не
устанавливает торговый результат и не переписывает историю.

Создание и отмена остаются торговыми командами через FIX с отдельным
подтверждением приёма Gateway. Перед отменой проверяются текущая активная
строка и исходная локальная заявка; для внешней заявки без локального запроса
возвращается 409. Фиктивные заявки и исполнения не создаются.

Проверки охватывают идентичность JSON, точность 19-значных номеров, decimal,
`null`, новые поля, разграничение FirmId, пагинацию и очистку текущего набора.
Интеграционные тесты запускаются только с `QUIK_ORDERS_TEST_DATABASE_URL`
на одноразовой БД с именем, оканчивающимся на `_test`.
