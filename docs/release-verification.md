# Проверка торгового релиза

## Unit-тесты

`go test -race ./internal/orders ./internal/outbox ./internal/api` из backend.
Правила quantity/open-order проверяются отдельно от PostgreSQL: точная граница,
десятичное превышение, наследование общего лимита, персональная пауза, освобождение
места и отказ при недоступности источника количества открытых заявок.

`npm test` из frontend проверяет также обработчики новых компонентов: сохранение
только разрешённых полей, сохранение формы при конфликте версии, запрет действий
по роли, курсор истории, отсутствие закрытия без доказательства и комментарий.
Это компонентные проверки с контролируемыми hooks, не браузерные E2E-тесты.

## Отдельный Docker-стенд

Запускать из корня проекта, требуется Docker Compose с поддержкой `!override`:

```powershell
docker compose -p fix-gateway-verification -f deploy/docker-compose.local.yml -f deploy/docker-compose.verification.yml up -d --build --wait --wait-timeout 180 access
node scripts/verify-trading-release.mjs
docker compose -p fix-gateway-verification -f deploy/docker-compose.local.yml -f deploy/docker-compose.verification.yml down -v
```

Проект использует отдельные volumes и порты 38080/38443/35432. Gateway подключён
только к внутренней Docker-сети, FIX направлен на симулятор. Скрипт проверяет
проект и владельца HTTP-порта до торговых запросов. Не направлять его на UAT.

Проверяются миграции до версии 25, настоящая заявка и ACK от симулятора,
восстановление очереди после моделируемого окна сбоя, автоматическая сверка,
сохранность send fence, отсутствие повторного claim, идемпотентный повтор,
торговая пауза, история и сохранность настроек после перезапуска.

Также выполняется pg_dump/pg_restore в отдельную БД с проверкой количества заявок,
исполнений, outbox, решений сверки, изменений лимитов и send fence. Gateway
запускается с восстановленной БД и должен достичь ready. Отдельная проверка
пересоздаёт gateway и подтверждает сохранность FIX volume. Это проверка механизма
локального восстановления, а не гарантия допустимости отката sequence numbers
на реальной ARQA-сессии.

Окно сбоя моделируется записью stale PROCESSING, затем gateway действительно
перезапускается. Дополнительно проверяется реальный обрыв TCP: режим симулятора
`SIM_FAULT_SYMBOL=FAULT_RECOVER` принимает NewOrderSingle, разрывает соединение
до ACK и передаёт сохранённое подтверждение после следующего Logon. Скрипт
проверяет открытый случай без доказательства, его автоматическое закрытие после
позднего ER и ровно одну отправку по журналу симулятора. Для детерминированной
проверки outbox дополнительно моделируется незавершённое PROCESSING-состояние.

Режим неисправности включён только в verification override. Его состояние
площадки хранится в памяти процесса симулятора; перезапуск самого симулятора
не покрывается этим сценарием. Совместимость восстановления с ARQA подтверждает
только отдельный согласованный UAT.
