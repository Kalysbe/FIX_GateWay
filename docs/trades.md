# Сделки

По поручению пользователя 02.11.2026 Gateway не хранит сделки. Их единственный
источник — таблица `public."Trades"` БД QUIK (`QUIK_EXPORT_DATABASE_URL`, только
чтение). Таблицы `trades`, `trade_sides`, `trade_reports`, `trade_side_reports`,
`trade_sync_runs` и `executions` удалены миграцией 40 вместе со сверкой и её
тревогами `TRADE_*`, командой `trade-reconcile` и настройкой
`TRADE_RECONCILIATION_ENABLED`.

| Потребитель | Что отдаётся |
|---|---|
| `GET /api/v1/trades` | Строки `Trades` фирмы токена (`FirmId` = `quik_firm`, при пустом — код брокера) |
| gRPC `trade.created` | Новая или изменённая сегодняшняя строка фирмы в `Event.data_json` |
| `GET /api/v1/admin/trades` | Строки всех фирм; `firm_id` и `broker_id` сужают выборку |
| Страница «Сделки» | Та же выборка постранично; карточки сделки нет |

Строки передаются как результат `row_to_json`: без переименования, пересчёта и
добавленных полей. Каждая строка — одна сторона сделки, обе стороны сводит сам
QUIK. Страницы — `limit`/`offset`, заголовки `X-Has-More` и `X-Next-Offset`.
Строки ограничены глобальной настройкой классов (`docs/market-data.md`). При
недоступности БД QUIK ответ — 503, данные не подменяются.

## FIX-отчёты об исполнении

Отчёт по-прежнему сначала попадает в постоянную очередь `inbox` на диске, а затем
меняет статус локальной заявки, пока она хранится (`docs/orders.md`). Исполнение
нигде не записывается. Повтор отчёта не меняет итог: `CumQty` абсолютен. Отчёт по
заявке, которой здесь нет (внешней или уже удалённой), не требует действий: её
результат есть в QUIK.

Транспортный журнал `backend/internal/fixaudit` остаётся на томе FIX
(`<FIX_SESSION_DIR>/<adapter-id>/audit/*.audit.jsonl`): это журнал обмена по FIX, а не
реестр сделок. Тревоги `EXECUTION_INBOX_BLOCKED`, `FIX_AUDIT_CAPACITY_<adapter-id>` и
`FIX_SEQUENCE_RESET_<adapter-id>` работают как прежде.

Контроля полноты сделок на стороне Gateway больше нет: он сравнивал копию с
QUIK, а копии теперь нет.
