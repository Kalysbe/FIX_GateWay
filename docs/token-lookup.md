# Поиск API-токена

В разделе **Токены** можно вставить полный токен брокера, его UUID или префикс
из восьми символов. Допускаются `Bearer ` перед полным токеном и `…` после
видимого префикса. Длинный токен ищется только целиком: совпадения первых
символов недостаточно. При нескольких совпадениях префикса нужно выбрать
конкретный токен; выдача ограничена 20 строками.

Карточка содержит название и ID токена, брокера и его состояние, фирму QUIK,
права, даты создания/истечения/отзыва, связь с предыдущим токеном при ротации,
последнее зарегистрированное использование и IP. Дополнительно показаны
лимиты запросов и заявок брокера и его ограничения по IP. Лимиты принадлежат
брокеру и не являются отдельной квотой найденного токена.

Истёкшие, отозванные и отключённые токены доступны для поиска. Если у ACTIVE
токена прошёл срок, карточка показывает EXPIRED без изменения записи в БД.
Просмотр не использует токен для аутентификации и не обновляет `last_used_at`.
Отсутствие этой отметки показывается как отсутствие данных об использовании.

API доступен только с действующей административной сессией, с теми же
правами чтения, что и существующий список токенов:

- `POST /api/v1/admin/tokens/search`, тело `{"token":"<значение поиска>"}`,
  ответ `{tokens: [...], has_more: false}`. Полный токен не передаётся в URL.
- `GET /api/v1/admin/tokens/{uuid}`, ответ `{token, broker, ip_whitelist}`.

Ответы имеют `Cache-Control: no-store`. Секрет и хеш не возвращаются.
Поле ввода очищается после отправки; поиск не сохраняется в браузерных
хранилищах, ключах запросов или кеше мутаций. Карточка запрашивается по UUID.
В аудит записываются факты TOKEN_LOOKUP/TOKEN_INSPECTED и ID найденных записей,
без строки поиска и тела запроса. Проверка поддерживает текущий HMAC-хеш
и прежний формат хеша. Восстановление полного токена из хеша не выполняется.

Проверки: тесты нормализации ввода, запрета неавторизованного доступа и выдачи
секрета; интеграционный `TestTokenLookupDatabase` запускается только с отдельной
одноразовой БД в `TOKEN_LOOKUP_TEST_DATABASE_URL`. Он проверяет оба вида хеша,
неактивные токены, коллизии префиксов, границу выдачи, аудит и отсутствие
изменений в данных токена. Торговые операции для проверки не требуются.
